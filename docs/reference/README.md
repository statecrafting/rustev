# Spec reference

One page per specification in [`specs/`](../../specs/), generated by
[spec-spine](https://github.com/statecrafting/spec-spine) from the registry
and the committed codebase index (spec `071`). Each page shows:

- **Lifecycle**: status, implementation state, creation date, supersession.
- **Requirements**: every obligation (invariants, requirements) with its
  anchor in the spec.
- **Ownership**: the files, directories and crates the spec establishes or
  extends, and whether each resolves in the index.
- **Evidence**: the spec's declared acceptance commands. They are declared,
  not executed: a page never says that a test ran or passed.
- **Changes**: what the spec amends or supersedes, and what amends it.

The spec text itself is the contract; a page restates its declared records.
For the current status of every spec at once, run `spec-spine registry list`
or read each page's Lifecycle table.

## Generated, never edited

Every region of a page except `notes` is generated. Do not edit a generated
region: the next generation overwrites it and `make gate` refuses it. If a
page is wrong, fix the source it came from (the spec, a claimed path, or the
index) and regenerate.

The `notes` region at the end of each page is authored text, kept across
generations.

```sh
make refresh          # regenerate the shards and these pages
make reference-check  # compare the committed pages with a fresh generation
```

The export is declared in [`request.json`](request.json).
